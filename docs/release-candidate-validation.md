# Runtime candidate validation: StormLib migration

This is an evidence summary, **not an acceptance gate**. The runtime candidate
`sha256:f386a33cd646331d6f10d91cf475db661de1dcf303417b2f94923b4e9124ae09`
was built from the source context recorded by the build receipt at commit
`ae6a86ba968283092eca67ba8fa6ed44fd09e16b`. Its source digest is
`31553cd96ca2fb4c70a6483f6f6096f77be593966505734e055cbbd12d169`.

- Native GHost++ and StormLib 9.24 were compiled from pinned upstream source; the historical GHost++ StormLib port was not compiled or linked. Native source provenance matched the checkout. A later independent no-cache native rebuild produced byte-identical GHost++, StormLib and BNCSutil binaries. A separate no-cache helper rebuild matched the candidate after ignoring only PE timestamp and checksum fields. A full no-cache Wine rebuild completed its build steps but was stopped by the 300-second limit while exporting the image; comparison of its final layers remains unverified.
- The candidate's Python phase-3 suite ran 241 tests successfully, with two optional tests skipped; the relay suite ran 152 tests successfully. Tests used a network-disabled container and synthetic account data.
- The MPQ suite passed 31 tests with the explicitly supplied Footman map and its matching hash, including a regression proving a failed MPQ open does not close stdin.
- A separate native build with AddressSanitizer and UndefinedBehaviorSanitizer passed 73 gameplay and 7 publication tests. It used the same native source and StormLib revision, not the production binary. It included a real-time 66-second solo AI match and rehost.
- An offline 900-second soak with the original Star and operator-supplied game metadata passed after 1013.478 seconds total. It checked cold start, persistent prefix restart, native recovery, SQLite persistence, orderly stop, no remaining vendor processes or zombies and no game engine process. The container reported no OOM.
- A separate offline supervisor cohort test passed in 139.554 seconds: duplicate profile ownership rejection, Star and relay SIGKILL recovery without native restart, native SIGKILL recovery, operator stop/start, SQLite persistence, no false online readiness, and no remaining processes.
- An actual synthetic profile was generated by the final image without networking; both files had mode 0600.
- The final image's 21 filesystem layers passed the path-based proprietary/profile-file audit. A separate scan of 21 layers and 15,453 files against values from the operator-provided account file found no matches; values were not logged. Automated scans cannot rule out every possible secret.
- The Docker release archive loaded locally and retained the candidate image ID. GitHub Actions passed on the corresponding main commit.

**Not established:** a completed no-cache build of the Wine base, actual iCCup authentication or a real-client match on this candidate. Actual online authentication and gameplay are separate from the offline gate. No release identity or acceptance gate has been issued for this candidate.

## Angel Arena candidate under validation

The subsequent candidate is
`sha256:75dbe33fe9d097ff7a5d64734a62126cf54b17a8df14bd4c7764880e4d045527`.
Its only runtime change permits an empty optional `war3map.wts`; required MPQ

v1.70b was analyzed inside this image: the static analyzer found 12 human
slots, and its generated preset compiled with AI and auto-start disabled. No map script
or Warcraft engine was executed, and this is not a gameplay or AI claim.

An independent no-cache Wine build completed; the package list and every file
under `/opt/wine-stable` matched the previously verified base. A separate
no-cache final packaging build used the same base IDs and source digest;
runtime source, libraries and GHost++ matched, and the helper matched after
excluding PE timestamp and checksum fields. The phase-3 suite passed 251 tests
(four optional skips), and 152 bridge tests passed. A separate offline cohort
test recovered Star, relay and native GHost after SIGKILL, preserved SQLite,
reported no false authentication, and found no remaining vendor processes or
zombies. A 21-layer path audit passed; a content audit of 15,453 image files and
159 source files found no match for either line of the operator-supplied
credential file. Neither credential value was printed.

The new image archive was loaded successfully and preserved the candidate ID.
A 900-second offline soak completed in 1012.134 seconds with the original Star,
synthetic profile, no network and no game-engine execution. It verified cold
and persistent-prefix starts, native crash recovery, SQLite persistence and
orderly stop; no zombie processes or OOM kills were observed. AMP dynamic
selector validation remains in progress. No gate or release identity has been
issued for this candidate at the time of this record.
